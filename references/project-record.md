# 项目记录与续作

只在多资产或跨轮次项目中使用，不为单次短回答创建空目录。产物保存在用户指定位置或当前工作区，避免覆盖原件。

建议项目结构，按实际产物创建：

```text
项目名/
  brief.md
  character-bible.md
  assets/
  production-prompts.md
  qa.md
  manifest.md
```

brief.md 记录目标、受众、场景、硬约束、偏好、假设、交付清单。character-bible.md 使用角色规范中的身份卡；保持一份当前基准，不复制出多份相互矛盾的规范。

manifest.md 的每个资产记录：文件名、用途、版本、使用的角色基准、状态、相关 QA。状态可为草案、工作基准、用户确认、被替代。记录“用户确认”须有实际依据。

恢复项目时先读 manifest 和身份卡，确认本次修改的对象、版本与范围，再读取相关图片和 QA。修改核心特征后，列出受影响的延展，不能把旧版延展当成新版成品。

production-prompts.md 保存实际采用的提示词、参考资产、工具名称和可取得的生成参数；不要编造种子或不可见参数。qa.md 保存观察与修订结果，不保存无关对话。

## 恢复点

在 manifest.md 顶部维护一段简短状态，每完成一个阶段或遇到阻碍时更新：

```text
本次范围：要求的产物与数量
当前阶段：定位 / 方向 / 身份 / 主形象 / 延展 / 交付
阶段状态：进行中 / 已完成 / 受阻
身份基准：角色卡版本与实际参考图路径
已完成：实际资产及相关验收记录
待完成：剩余必需项
阻碍：具体缺少的输入或能力；无则写无
下一步：一个可以继续执行的动作
```

恢复时先检查所列文件是否存在并查看相关参考图。遇到记录与文件冲突，以实际文件和用户最近指令核对，不能只凭“已完成”文字跳过缺失产物。

身份基准变更后保留旧文件，将受影响的旧延展标为“待复查”，逐项检查后再转为新版可用资产；未经复查不能仅批量改版本号。
